# 歌词匹配率修复（当前 9/24 成功）

## 实测数据（我在本机跑的，你自己复现请用同样脚本）

诊断脚本：`C:\Users\tianz\AppData\Local\hermes\cache\scratch\diag_lyrics2.js`
（它搜 6 个关键词，每个取时长 120–480 秒的 B 站结果，调 `app/bili/lyrics.js` 的 `match()`）

当前结果：**成功 9 / 失败 15（37%）**，失败全部是「没有候选过线（时长 / 标题 / 歌手对不上）」。

## 已定位的三个原因

### 原因 1：搜索关键词用了「原始长标题 + UP 主」

现在 `match()` 拿 `标题 + UP主` 当关键词去搜。实测这种长查询会**把相关候选挤掉**：

| B 站标题 | 用原文搜网易云 | 用「歌名 歌手」搜 |
|---|---|---|
| `《夜曲》周杰伦丨百万级录音棚试听丨【Hi-Res无损】` | 返回「杯酒 - 双截棍…说唱 Type Beat」等**完全不相关** | `夜曲 / Xai小爱 / 234s`（翻唱，但至少是这首歌） |
| `【无损音质】陈奕迅-孤勇者「爱你孤身走暗巷…` | 有 `孤勇者 / 陈奕迅 / 256s` | 同样有 |

而且 `parseBiliTitle()` 已经能从标题里抽出「可能的歌名/歌手」，只是**没用于搜索**（只用于打分）。

**改法**：搜索关键词优先用 `names[0] + artists[0]`（抽出来的「歌名 歌手」），**两个源都用**；
抽不出东西（names 为空或与原文相同）时才退回原文标题。UP 主**不再拼进关键词**（它常常是搬运号，反而是噪音）。

### 原因 2：时长容差 4 秒太严

`MAX_DUR_DIFF = 4`。B 站视频普遍带片头片尾，差 5–15 秒很常见。
**改法**：放宽到 **10 秒**；10–20 秒之间的候选允许存在但**总分打 8 折**；超过 20 秒才淘汰。

### 原因 3：周杰伦这类歌网易云无版权，只能靠 LRCLIB，而它常 503

实测 `稻香` 的 3 条成功全部来自 `lrclib`，网易云搜不到原版（只有翻唱）。
`lrclibSearch()` 现在只重试 1 次、等 800ms。
**改法**：重试 **3 次**，退避 600 / 1500 / 3000ms；三次都失败才放弃并在 `reason` 里说明。

## 另外要做的：失败时返回候选明细

`match()` 失败时，除了 `reason`，再返回 `candidates`：按总分排序的 **top 3**，每条 `{ source, title, artist, durationSec, titleScore, artistScore, total, rejected }`
（`rejected` 说明为什么被淘汰：`'时长差 23s' / '总分 42 < 55'` 之类）。

用途：(1) 我诊断时能直接看卡在哪一步；(2) 将来做「手动选歌词」时可以直接把这几个候选列给用户。
